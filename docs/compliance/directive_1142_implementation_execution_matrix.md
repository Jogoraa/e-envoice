**Current Architecture:** Java 21, Spring Boot 3.3.x, PostgreSQL 16 (RLS, Audit Chaining, Outbox), Flutter / Dart (Riverpod, Drift, Offline Sync)  
**Standard:** Zero-Hallucination Legal & Technical Verification Gate  

---

### Status Vocabulary

- `NOT_STARTED`: The requirement is identified as applicable and missing or incomplete, and implementation has not yet commenced.
- `IN_PROGRESS`: Active implementation (backend, database, or UI) is underway.
- `SOFTWARE_VERIFIED`: Complete internal software implementation exists (entities, DB constraints, RLS, API, RBAC, audit, PostgreSQL integration tests, negative tests, Flutter UI where applicable) and all automated verification passes with zero mocks in production path.
- `READY_FOR_EXTERNAL_ACTIVATION`: Internal software implementation is fully complete and verified, but live production operation requires external authority/third-party activation (e.g. taxpayer-specific MoR sandbox credentials, live EIRS API, live INSA HSM/certificates, bank guarantee issuance).
- `EXTERNAL_DEPENDENCY`: Pure external regulatory, legal, or governmental dependency outside platform software control (e.g. MoR Accreditation Board establishment, official Gazette publication).
- `NOT_APPLICABLE`: Requirement does not apply to UT Invoice (e.g. hardware fiscal cash register manufacturing, internal enterprise private self-development) with legal/technical justification documented.
- `BLOCKED`: Implementation cannot proceed due to an unresolved upstream prerequisite.
- `FAILED`: Automated verification or compliance audit detected a defect or regression.
