### Strict Status Taxonomy:
- `CODE_VERIFIED`: Directly implemented in repository source code and proven by automated unit, integration, or adversarial tests.
- `SPECIFICATION_VERIFIED`: Checked against an authoritative technical specification available in the repository.
- `INFRASTRUCTURE_EVIDENCE_REQUIRED`: Architectural design and deployment configurations present; requires physical infrastructure / hosting operational evidence.
- `INSA_APPROVAL_REQUIRED`: Procedural software security evaluation and cryptographic certificate issuance by INSA required.
- `MOR_APPROVAL_REQUIRED`: Ministry of Revenues Accreditation Board testing, sandbox validation, or formal accreditation license required.
- `PROCEDURAL_APPROVAL_REQUIRED`: Corporate, legal, financial, or staffing prerequisites (e.g. business license, bank guarantee, engineer degrees).
- `NOT_IMPLEMENTED`: Requirement within scope but not implemented in current codebase.
- `UNKNOWN`: Unresolved requirement pending clarification from regulatory authorities.
